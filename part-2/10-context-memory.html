第 10 章 · 记忆是这样被读取的

备菜台——窗口有限，取舍有方

第 9 章结尾说：执行日志记录一切，可记录不是为了供着。这一章看「读取」——执行日志和文件里的记忆，怎么变成模型眼前的上下文。这是记忆线的「消费」一站：7 提供 → 9 记录 → 本章消费 → 8 写回。全章一个比喻：厨房——库房（执行日志与文件）很大，备菜台（上下文窗口）很小，模型就着台面炒菜；台面装不下，就把历史熬成高汤。

◆核心问题

日志和文件里的记忆，怎么变成模型眼前的上下文？

▶你将获得

看懂上下文组装与压缩——为什么 Agent 有时会「失忆」，如何喂得高效。

本章导览

10.1 从黑匣子到备菜台：历史投影

库房很大，台面很小。模型每一轮请求看到的，只是备菜台——本次请求的上下文。开工前，五样原料被拼上桌：

  • 系统提示——身份、规矩、工作方式（第 21 章的主角，这里先摆上）；
  • 工具说明书——第 8 章见过：能叫哪些工具、每个工具的参数长什么样；
  • 你的消息——本次任务的直接指令；
  • 注入的指令——第 8 章的交接框：AGENTS.md 链原文；
  • 历史投影——第 9 章的黑匣子：此前说了什么、模型回了什么、工具交了什么。
图 10-1 备菜台组装：系统提示、工具说明书、你的消息、注入指令、历史投影——模型只看见台面。

其中「历史投影」最值得细看：日志是真相全集，模型只吃子集。每轮请求前，session-projection 把日志里的记录投影成「模型可见的历史」——第 9 章图 9-2 的那条「投影」箭头，机制就在这里。投影不是复制：打包行还原成一条条分片，与请求无关的派生记录不上桌。所以最后交给模型的结构是：

── 系统提示 ──────────────────────────
你是 dsh，一个编码 Agent：身份、规矩、
可用工具总目录（第 21 章细讲）

── 工具说明书（节选）────────────────
read 读取文件 · write 写文件 · bash 跑命令
（名称 · 用途 · 参数，第 8 章 8.2）

── 你的消息 ──────────────────────────
帮 packages/schedule 写一个 cron 调度插件

── 交接框 system-reminder ────────────
The following workspace instructions may be
relevant to your work…

Instructions from: AGENTS.md
DeepSeek Harness is a plugin-based agent
harness on vendored Cordis: everything is a
plugin. Read docs/architecture.md before
changing packages/…
（原文照登 · 第 8 章）

── 历史投影（节选）──────────────────
你：帮 packages/schedule 写一个 cron 调度插件
Agent：先摸清现状（调用 read）
工具：packages/schedule/src/… 已读
Agent：参考 croner 搭插件骨架（调用 write）
…（再长的历史，装不下就熬成摘要 · 10.2）

五样原料按这个顺序拼成一次请求——「最终长什么样」现在看得见了。第 8 章只答应「原文照登三保证」，完整的拼装流水线看 10.3；台面装不装得下，看下一节。想再往里走一步：这五样在 dsh 体内是怎么一步步拼出来的，是第 13 章《Agent 是怎么拼起来的》「上下文与模型分工」一站的事（创造线看体内）；一个完整回合怎么转起来，第 16 章见。

10.2 台面有限：窗口与压缩

备菜台不是无限大。上下文窗口有 token 预算：dsh 的指令注入就要求部署者显式选一个 maxBytes，拒绝「默认无限」。会话越长，历史这味原料越堆越高，眼看要漫出台面——这时轮到压缩（compaction）上场，把用剩的原料熬成高汤：

  1. 察觉压力——compaction-basic 在每步开工前的关卡检查水位。这关卡就是第 8 章 8.1 埋过种子的 pre-step——正式学名 agent/pre-step，每一步开工前广播的生命周期事件，谁挂监听谁干活（事件与监听机制，第 15 章展开）；只有「规范的上下文溢出」才走报错通道；
  2. 先剪枝——可选的无模型工具结果修剪（ctx.toolResultPruner）：把过期的超大工具结果裁掉，不花模型的算力；
  3. 再熬汤——挑历史生成摘要，替换掉可见表层的大段原文；摘要本身也追加进日志（第 9 章的「压缩」派生，就在这里闭合）；
  4. 在新一轮里恢复——压缩在失败的一步之后、这一回合结束之前完成，下一个回合拿着高汤继续干。
图 10-2 窗口与压缩：水位超线先剪枝再熬摘要；摘要落日志，下个回合接着干。

所以 Agent 突然「忘了前面说过的话」，多半不是故障——是台面装不下、高汤没熬到那句。想验证，回第 9 章的黑匣子：摘要落日志的那一行，就是取舍发生的现场。

⇄双线提示 · 创造线视角

这套「先剪枝、再摘要、落日志、新回合恢复」的四步，是你设计任何长程 Agent 都该照抄的骨架；dsh 还把它包成了用户命令 command-compact——不等水位报警，你随时可以主动熬一次汤。

机制上可以一直压下去，但策略上「已经压缩过多次」本身就是一个信号——该考虑把工作记忆换成外置记忆了。看三个信号：

  • 高汤已经熬到第二锅——摘要的摘要开始漂移，早期精确细节（路径、报错原文、当时的约定）一层层变模糊；
  • 主线还长——任务离终点远、上下文依赖重，继续压下去每一步都在吃漂移的亏；
  • 你（人）已经看不清现场——几百步的会话，复盘成本已经高过续写的收益。

三条占两条，就先交接、再新开：让 Agent 把进展写回文件（做完了什么 · 卡在哪 · 下一步是什么，决策的「为什么」进 notes），新会话带着 AGENTS.md 与那份交接文档重新开工；旧日志留在 DSH_SESSION_ROOT 随时可查——它不是消失了，只是不再当工作记忆。反过来，只差临门一脚、关键细节还没落盘时，就再压一次把它干完——干完立刻写回。

10.3 三层记忆，怎么被吃掉

第 7 章清点过「三层记忆放在哪」（见 7.2 三层记忆，忘了的读者可回补一眼），本章补另一半：它们各自怎么被吃。先看人记的 AGENTS.md 链——第 8 章说「原文照登、三保证」，完整的组装流水线是五步：

  1. 收——按家规 → 项目链 → 本地小抄的顺序把手册全部读回来；
  2. 去重与裁剪——内容相同的 AGENTS.md 与 CLAUDE.md 只留一份；总量超过预算（maxBytes）时，超出的文件被省略——是「不放进请求」，不是「压缩成摘要」；
  3. 包框拼接——剩下的手册原文一条条拼进 system-reminder 交接框，每条注明出处（Instructions from: 路径）；
  4. 折进第一步——这条消息紧跟你的消息之后，一起进入第一次模型请求；
  5. 交给模型——原文照登，不是摘要。

五步收口，就是 10.1 里的交接框；保鲜（「走到地盘」补更新条）第 8 章已讲，这里不重复。三层记忆各吃各的——吃之前先分清两条轴：谁读（层的名字是「谁写」，读的使用方未必是同一方）与谁拍板（机制注入 · AI 自判 · 你点名，三种触发器）。生产侧本章不展开（谁写在第 7 章、何时写在 8.3 写回），但表里顺手标出——生产 → 存放 → 消费，一条线看全。同一层里吃法不同就拆成两行，每行只挂一个触发器：

记忆层 · 文档谁拍板写 · 何时写使用方（谁读）谁拍板 · 何时读怎么读
人记 · AGENTS.md 链（家规 → 项目 → 小抄）人拍板 · 立规矩时AI机制：每次开工注入五步流水线原文注入

表里「怎么读」再补一问：读到的是整篇，还是节选？三种读法，三种答案：

  • AGENTS.md 注入——整篇照登：预算内的文件全文进框，不节选、不摘要；超预算的整份省略（五步流水线里的「裁剪」），去重与路径链是另外两道闸；
  • docs · notes 翻读——读多长由 Agent 定：read 工具带 offset / limit 参数（第 8 章 8.2 的说明书），它可以只读相关段落，也可以整篇翻；超大工具结果还有剪枝兜底（10.2 的 toolResultPruner）；
  • 历史投影——子集 + 摘要：投影本来就不是全集，再装不下就熬成摘要。

一句话：只有「历史」会被熬成摘要；文件记忆要么整篇照登，要么由 Agent 自己决定读多长。

「谁拍板写」还藏着第二层：动手的未必是拍板的——生产侧同样是两条轴，谁拍板写（决定权）与谁动手写（落笔权）。四类文档，四种组合：

  • 人记（AGENTS.md · docs）——人拍板、Agent 代笔居多：你口述约定，Agent 用 write 工具落笔（8.2 的「模型出主意、工具动手」，生产时一样成立）；
  • skills——也是人拍板：作业指导书的步骤与合格线人定，dsh 的 11 个技能皆然，Agent 常提建议、常代笔；
  • notes——Agent 自定自写：决策「为什么」它自己记，人只做事后审查；
  • 机器记 · 日志——两头都是机器：流水线到点自产。

一句话：判断在人，落笔多在 Agent，机械活全交给流水线——和第 6 章「判断越关键越留给人」是同一句。

图 10-3 三层记忆加日志，四条通道流向同一张备菜台；吃出结果，再走第 8 章的写回。

串一遍真实场景：你在 dsh 仓库里让 Agent 改 packages/ 下的代码，同一次会话里走遍五种吃法：

  1. 开工——AGENTS.md 链进交接框（每次注入）；
  2. 动手前——按根约定的点名，Agent 自己判断用得上，用 read 工具翻开 docs/architecture.md（用到才读：路牌在 AGENTS.md，抬腿的是它自己）；
  3. 改到旧代码——先翻对应的 .agents/notes，找回当初「为什么这么定、放弃了什么」，改得有理有据，而不是把避开的坑填回去（第 7 章有现成例子：改版本号之前先读 Note）；
  4. 活干得长——压缩把老历史熬成摘要写回日志；
  5. 收尾——你下载整份日志复盘。

七种吃法里，这里一口气走过五种——剩下两种（技能调用、守门工具查）分别等第 11 章和提交时刻登场。

一条总原则：越机械、越通用、越需要一致性的知识，越该进文件（让注入替你喂）；越具体、越临时、越私密的，留在对话里。文件是「培训」，对话是「现场」。落到第 8 章那句口诀，就是这四样：

▶四种吃法，一句口诀

AGENTS.md 每次必读 · docs 与 notes 用到才读 · skills 按需调用 · 机器记平时不上桌——路径外的层，走到才读。

一张图总结

图 10-4 备菜台全景：库房、备菜台、高汤、菜谱——一条回路把记忆转起来。

要点回顾

  • 备菜台五样：系统提示 + 工具说明书 + 你的消息 + 注入指令 + 历史投影——最后交给模型的就是这个结构。
  • 历史投影：日志是全集、上下文是子集；模型可见的必然可追溯（第 9 章的不变量）。
  • 台面有限：水位超预算先剪枝再熬摘要；高汤落日志、下回合接着用——「失忆」多半是取舍，不是故障。
  • 读记忆看两条轴：谁读——人记与 Agent 记给 AI 读、机器记给守门工具与 AI（事故档案）、日志 AI 和人双用；谁拍板——机制注入 · AI 自判 · 你点名；生产侧（谁拍板写 · 何时写，落笔多为 Agent）表里一并标出，生产 → 存放 → 消费一眼看全。
  • 压缩到第二锅就换锅：多次压缩后，先交接写回（进展 · 卡点 · 下一步进文件）、再新开会话，旧日志留档可查；只差临门一脚时再压一次干完、立刻写回。

动手做

  1. 开一次 dsh 会话干个小任务，在日志里找出交接框与历史投影并存的证据：system-reminder 段 + 它前面的 user/message。
  2. 挑一条你项目的 AGENTS.md 规则，确认它属于「每次必读」；再挑一篇 docs/ 概念文档，确认它是「用到才读」——把两类资料的边界想清楚。
  3. 想象一次长会话的上下文：数一数里面装了几层记忆；窗口爆了，哪些该先被剪、哪些该进摘要（高汤）？
▶回路钩子 · 记忆线的闭合

记忆线在这里走到「消费」一站：第 7 章提供（记忆放进文件）→ 第 9 章记录（过程落日志）→ 本章消费（投影上桌 + 熬高汤）→ 第 8 章写回（AGENTS.md · notes · skills 三去处）→ 再被第 7 章吸收。排序只是让章节相邻，钩子把回路接上——这就是「用 → 写 → 长」。

消费线还剩最机灵的一层没展开：skills 是「按需调用」的作业指导书——Agent 什么时候想起它、怎么把它调进来。第 11 章《技能是这样被使用的》。
