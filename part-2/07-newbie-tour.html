第 7 章 · 新人报到：先读懂这个项目

入职第一天：读懂这个被 AI 养着的项目

入职第一天，先读懂这个项目。第 4 章立了观念——会说话、有记性、会成长；第 6 章说，第二篇从项目开始。这一章兑现：把观念对号入座，完整解析 dsh 这只活标本怎么用 AI 工程化驾驭自己的项目——记忆分三层，成长靠一条回路。看懂这一章，等于完成了「新人报到」。

◆本章核心问题

dsh 是怎么用 AI 工程化驾驭自己的项目的？观念落在哪里、记忆分几层、成长靠什么？

◆全书心法 · 工程化

记忆靠文件，成长靠写回。

三层记忆——人记文档，Agent 记决策与技能，机器记复盘与检查。

▶你将获得

一张完整的工程化地图：观念对号入座表、三层记忆的清点、成长机制的四样证据、照做的四动作与体检清单——之后第 13 章再讲这些记忆在 Agent 运行时怎么用。

7.1 观念对号入座

第 4 章的观念有三个：会说话、有记性、会成长。在 dsh 身上，它们不是口号——每个观念，都有一件看得见、摸得着的实体。

观念（第 4 章）dsh 里的实体在哪一节展开
会说话（四特征）README · 仓库布局 · AGENTS.md · docs/7.2
有记性（外置记忆）三层记忆：人记（文档约定）· Agent 记（notes + skills）· 机器记（复盘 + 检查）7.2
会成长（用 → 写 → 长）约定自改 · 翻译流水线 · 格式版本化 · 事故复盘7.3
图 7-1 观念对号入座：说话、记性、成长，各有实体。

一句话总结：观念是「为什么」，实体是「长什么样」。这一章做的就是后一半——标本是 deepseek-harness。

7.2 三层记忆：人记 · Agent 记 · 机器记

第 4 章说，项目是 Agent 的外置记忆。dsh 的记忆不是摊在一处，而是住三层。先认个门——AI 工程化相关的东西，分别住在哪些目录里：

图 7-2a 工程化的目录地图：每一处写下的约定，都是这只活标本的记忆。

认完门，把地图收拢成三层：

图 7-2 三层记忆：人记文档与约定，Agent 记决策与技能，机器记复盘与检查。

人记：文档与约定

第一层，是写给人看、任何读者（包括 Agent）都要读的正式记忆。三个实体，各管一摊：

  • README——入口：这是什么、怎么跑、给 AI 的提示写在最显眼处；
  • docs/——概念文档（architecture、glossary、cordis-primer、agent-lifecycle、development、testing……）：概念写在前头，代码跟着概念走；
  • 子树 AGENTS.md ×8——作用域规矩：走到哪，就读得到当地的规矩，连 CI 都有一份。

这一层还有条分工法则，写在 docs/development.md里，原话是「设计依据与实现细节属于链接的 Agent Note」——翻译过来一句话：「怎么做」写进 AGENTS.md，「为什么」写进 Agent Note，两个文件各管一半，谁也不抢谁的话。

看一个真例子——「Node 引擎下限」：

  • 怎么做（指南）：一行就够——「Node.js 22.19+ 与 24+，pnpm 11.7.0」；
  • 为什么（Agent Note）：为什么是 22.19 而不是别的版本、权衡了什么，见 Node 引擎下限 Agent Note。

改版本号之前先读 Note：读完要么照旧，要么改得有理有据。

「怎么做」 · AGENTS.md「为什么」 · Agent Note
写什么命令清单、检查步骤、硬性规范设计依据、权衡、放弃了什么
什么时候读按部就班执行时想改动、想推翻时
例子「Node 22.19+ · pnpm 11.7.0」「为什么定 22.19 而不是别的」

运行时这套分工怎么被 Agent 用起来（怎么读、怎么写回）——第 8 章《让 Agent 写得出代码》再走一遍。

Agent 记：决策与技能

第二层，藏在点开头的目录里——.agents/，dsh 管它叫「Agent 的家」（DSH_AGENTS_HOME，默认 ~/.agents）。里面两间房：

  • notes/——Agent Note：记录代码和文档承载不了的东西，「为什么这么做」与「放弃了什么」，每份带状态（proposed → implemented / archived / rejected），目录自己也有 AGENTS.md 立规矩；
  • skills/——技能库：把「怎么维护这个项目」写成一册册作业指导书（代码审查、文档规范、翻译、归档笔记、推送前检查……十一个技能），换哪个 Agent 来，拿起来就会。

想看实物：notes 的约定、一个技能示例（GitHub 源码）。

机器记：复盘与守门

第三层没有「人」参与——机器当记忆，像仓库里三个全年无休的门卫：事故档案员（postmortem）、翻译校对员（i18n 流水线）、提交闸机（lefthook + knip）。他们不创造记忆，只让记忆不失效、不走样、不重演。

  • 事故档案员：docs/postmortem/——每次事故写成一份编号复盘，每份配双语：0001 是「ACP 默认导出丢了 inject」，0004 是「landlock 部分告警被误判成子进程失败」——事故经过、根因、预防一条龙。编号递增，档案越厚，同一个坑越难踩第二遍。
  • 翻译校对员：*.i18n.yaml + docs/i18n/——每份文档都配一份 i18n.yaml（连复盘档案都配），术语表与风格样例管着译文不走样；提交时钩子当场对账（verify-translation-pairing），英文改了中文没跟上，直接拦在门外。
  • 提交闸机：lefthook.yml + knip.json——pre-commit 三个岗位：翻译配对校验、归档笔记校验、lint（oxlint 顺手修掉再放行）；knip 再扫一遍死代码与未用依赖。本地关卡要快，CI 才管大闸——坏东西进不了仓库。
门卫装备拦住什么
事故档案员docs/postmortem/ 编号档案同一个坑踩第二遍
翻译校对员*.i18n.yaml + 术语表双语不同步、术语走样
提交闸机lefthook.yml + knip.json坏提交、死代码

管理原则只有三条，恰好对应三层：作用域化（人记——走到哪读到哪）、文档先行（人记与 Agent 记——概念和「为什么」写在前头）、机器可处理（机器记——结构化的流水线，跟进不靠人）。

这些上下文在 Agent 运行时怎么被读、被管理——第 10 章《记忆是这样被读取的》再讲。

7.3 成长的机制：写回与流水线

成长的机制不是「勤奋」，是「写回」的约定，加上机器化的流水线。四样证据：

  • 约定自己会改：根 AGENTS.md 里有一节写着「Remove this section at the first tagged release」——约定文件随项目阶段更新，阶段一到就删，不带着旧规矩过河；
  • 写一遍，自动跟进：每份文档配 i18n.yaml（如 README.i18n.yaml），写回一次，翻译流水线自动同步多语言；
  • 格式有版本：SQLite 的 SCHEMA_VERSION 单调递增、dsh-session 的 SESSION_FORMAT_VERSION 显式声明，旧格式直接拒收——成长的每一步都留痕、可追溯；
  • 坑不踩第二遍：每次事故写进 docs/postmortem/ 编号归档，每次决策写进 Agent Note 并随状态机流转——复盘与决策都进仓库，下次自己会读。
图 7-3 成长的回路：协作 → 写回 → 机器跟进 → 下次更顺，实体化第 4 章的「用 → 写 → 长」。

和第 4 章 4.4 的「用 → 写 → 长」是同一件事——现在你看到的是它的实体：回路不是比喻，是仓库里的约定、笔记和流水线。

7.4 你的项目照做：四动作与体检

工程化的方法可以复制。四特征 → 四动作，然后体检：

特征动作最小可做
文档可读写自述补三行 README：是什么 · 怎么跑 · 怎么改
结构清晰理结构拆开一个千行文件，按职责分层
约定显式立规矩新建一份 AGENTS.md，写下三条 AI 协作规矩
上下文易取收上下文把聊天记录里的一条结论，写进文档
◆先最小，再迭代

不用一次做齐。每个动作都有「最小可做」的版本——做完就跑起来，下一次协作再改。记住：写不完美没关系，回路会帮你改。

检查项通过标准打分
自述新同事 5 分钟看懂 README0 / 1 / 2
结构想找的东西 10 秒找到0 / 1 / 2
规矩规则写在文件里，不靠默契0 / 1 / 2
上下文关键信息都在仓库，不用问人0 / 1 / 2
回路上次协作的结论，已经写回仓库0 / 1 / 2
✦体检不是一次性的

每次协作结束，都该回来打一次分。第 4 章说过：回路转起来，项目越用越活——这张表就是回路上的仪表盘。

一张图总结

图 7-4 第七章的完整脉络：对号入座 → 三层记忆 → 成长四机制 → 照做体检。下一章：同一标本的第二种眼光。

要点回顾

  • 观念有实体：会说话 → README/AGENTS.md/docs/；有记性 → 三层记忆；会成长 → 写回与流水线。
  • 三层记忆：人记文档与约定（怎么做）、Agent 记决策与技能（为什么，.agents/ 的家）、机器记复盘与守门（postmortem · i18n · lefthook · knip）。
  • 成长四机制：约定自改、翻译流水线、格式版本化、坑不踩第二遍——写回，而不是勤奋。
  • 三条管理原则：作用域化 · 文档先行 · 机器可处理——恰好对应三层记忆。
  • 照做四动作（写自述 · 理结构 · 立规矩 · 收上下文）+ 体检清单，项目越用越活。
  • 这一章看的是「项目怎么被养」；下一幕上手用它开发——第 8 章《让 Agent 写得出代码》。

动手做

三件小事，今天就给项目做一次「对号入座」：

  1. 对号入座：打开你的项目，找出「人记 / Agent 记 / 机器记」各对应哪些文件——找不到的，就是下一轮要建的。
  2. 做一个动作：从四动作里挑一个，完成它的「最小可做」——补三行 README、拆一个文件、新建 AGENTS.md、或收一条上下文。
  3. （可选）读证据：打开 deepseek-harness 根目录的 AGENTS.md、.agents/ 里的一份笔记和一个技能，各写一句点评。

这一章看的是「项目怎么被养」。下一章把同一标本翻过来——第 8 章《让 Agent 写得出代码》：先上手，让 Agent 接得下活。
