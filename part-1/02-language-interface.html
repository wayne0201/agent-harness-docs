第 2 章 · 语言成为新接口

从「操作机器」到「与机器对话」。

第 1 章我们拆开了一个 Agent。这一章退后一步，问一个更大的问题：为什么是现在？答案不是「AI 更强了」这么简单，而是——机器终于学会了我们的母语。可母语有它的脾气：模糊、多义、讲概率。看懂新接口的三个侧面——语言、概率、意图——你就看懂了这场范式转移的全貌。

◆本章核心问题

为什么说 Agent 不是软件的升级，而是一场范式转移？

◆全书心法 · 新接口

接口换了语言，性质换了脾气，用法换了话术。

记住这三个「换了」——它们是后面每一章的地基。

▶你将获得

看懂这场范式转移的三条脉络——接口、概率、意图；之后每一章，都是这三条的展开。

2.1 三种语言：机器码 → 编程语言 → 自然语言

人和机器之间，永远隔着一层「语言」——它的学名叫接口。想让机器做事，就得用它听得懂的语言说话。

这门语言换过三次。每换一次，「能跟机器说话的人」就多一个数量级。

图 2-1 接口的三次换语言：机器码 → 编程语言 → 自然语言，能跟机器说话的人越来越多。

科普小站 · 语言简史

1940 年代，机器只听得懂打孔纸带上的 0 和 1——想跟它说话，先成为人类中的极少数。1949 年汇编语言登场，机器码被换成助记符，门槛第一次松动。1954 年 FORTRAN 问世，人们第一次能写接近数学公式的代码；此后 C、Java、Python 一路把语言往人的方向挪。

每一次迁移都是同一件事：把机器往人的方向搬一步。FORTRAN 让工程师写得了代码，Python 让几乎人人都能学——而这一次，机器干脆反过来，直接学我们说话。

自然语言成为接口，是史上第一次机器迁就人，而不是人迁就机器。门槛从「会编程」降到「会说话」。还记得第 1 章的私人助理吗？你不需要懂它的内部语言——它来懂你的。

2.2 从「算对」到「猜对」

但母语有它的脾气：模糊、多义、意思藏在上下文里。机器处理自然语言，靠的不是规则，是概率。

还记得 1.3 的「从确定性到概率性」吗？那里只是提了一嘴——这里把它展开成一个工程问题：软件的性质，变了。

打个比方：以前的软件像计算器——输入什么，输出什么，永远一致；错了就是 bug，找到就能修好。今天的 Agent 更像顾问——听个大意，给个大概率对的答案；错了是概率事件，下次错的还不一样。

图 2-2 从「计算器」到「顾问」：确定性软件的验收是测试，概率软件的验收是审查。
维度确定性软件（计算器）概率软件（顾问）
写代码用规则写死每一步用语言描述期望
出错有 bug，可复现概率事件，每次不一样
修复找到 bug，修掉喂上下文、调边界、重试
验收测试全绿审查结果 + 边界 + 评估

性质变了，工程手段就得跟着变，至少三件事：

  • 验收结果：不能「跑通就算完」，要像验货一样验收产出；
  • 立边界：不能只靠「找 bug」，要靠护栏把错限制在可控范围；
  • 持续评估：不能只测一次，要持续用数据确认「它到底变好没有」。

这三件事，正是第 15 章（信任与审查）和第 23 章（评估与质量）的主题，机制在第二篇逐个展开。先记住结论：跟概率共处，不是消灭概率。

2.3 从命令到意图

接口变了，话术也得变。以前对机器说话，用的是命令：每一步都要交代清楚，少一步它就卡住。现在对 Agent 说话，用的是意图：说清楚要什么、不要什么，中间的路由它自己走。

想象两种打车方式：坐以前的老车，你得一路指挥——「前面路口左转」「第三个红绿灯直行」；叫今天的网约车，你只需要一句「去机场，走高速，别绕路」——目的地 + 偏好 + 约束，剩下的交给司机。

图 2-3 命令式把每一步都说死；意图式只定目标、约束与边界，把路交给 Agent 走。

一句好意图，就是三个零件：目标（要什么）、约束（想怎么做）、边界（不能碰什么）。这三个零件，正好落在第 1 章心智模型的三个格子里：目标给「模型」去规划，行动交给「工具」去执行，上下文与边界写进「记忆」。

意图式说话，还是全链路的第一步：把一条链交给 AI 跑（第 6 章），前提就是你说得出目标、立得住边界。怎么把意图说好、边界立好——下一章（第 3 章）讲十六字心法，第 4 章讲怎么让项目活起来；创造线的那一边，第 5 章见。

一张图总结

图 2-4 第二章的完整脉络：接口 → 概率 → 意图，三个「换了」，一场范式转移。

要点回顾

  • 接口换过三次语言：机器码 → 编程语言 → 自然语言——每换一次，能跟机器说话的人多一个数量级；这一次，机器反过来迁就人。
  • 软件的性质从「算对」变成「猜对」：从计算器到顾问；工程上要用验收、边界、评估与概率共处。
  • 用法从命令变成意图：一句好意图 = 目标 + 约束 + 边界。
  • 这不是升级，是范式转移——所以这本书要从头重新教一遍「怎么跟机器打交道」。

动手做

把这一章的三个「换了」，用在自己身上：

  1. 改写一句命令：把今天要做的一件事，先写成给新人的逐步指令，再改写成一两句意图（目标 + 约束 + 边界）。感受两者的差别。
  2. 分辨计算器与顾问：列出你项目里的三个环节，标注哪些是「计算器」（必须算对），哪些是「顾问」（可以概率）。
  3. （可选）换一种说法：打开任意一个 Agent 产品，用「目标 + 约束 + 边界」的句式提一个需求，对比以前命令式的用法。
