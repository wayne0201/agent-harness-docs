第 3 章 · 与 Agent 共事的哲学

能力它给，边界你定

这一章写给这样的你：你有一个项目，想把它变成 AI 工程化的项目——让 Agent 进入你的开发流程。在谈任何工具之前，先在你的认知里种下一粒种子：你的团队里，即将入职一位行业内很资深的工程师。他懂行、能写、不知疲倦；只是刚入职，对你的项目还不熟悉。你的价值，不再是亲手写每一行代码，而是——上下文喂饱、管住边界、放手发挥、共同进化。

◆本章核心问题

我有一个项目，该怎么把 Agent 用好？哪些事交给 Agent，哪些留给自己？

▶你将获得

一套「与新来的资深工程师共事」的心法框架——这是 AI 工程化的第一粒种子，比任何具体工具都保值。

◆全书心法 · 十六个字

上下文喂饱、边界管住、放手发挥、共同进化。

记住这十六个字——它对应一位工程师的入职旅程：入职交接、试用期、转正、成为骨干，本章每一节是其中一站。

3.1 角色之变：从「亲手写」到「管边界」

也许你会问：该把它当什么？当工具？工具没有主动性，用完即弃。当实习生？实习生经验不足，需要你手把手教。都不准确。

它更像一位行业内很资深的工程师——只是刚入职：行业经验很足，代码写得快、技术懂得多、不知疲倦；但对你的项目还不熟——背景、约定、坑，一概不知。所以你不教它做事，只做三件事：喂上下文、管边界、做判断。

这意味着放下两种执念：放下「什么都得我亲手写」的执行者执念，也放下「我比它更懂」的优越感。你的价值，从「写得快」变成「想得清、管得住、判得准」。

图 3-1 执行者：每一环都要你亲手做，瓶颈是你的双手；管理者：你定目标、喂上下文、管边界，瓶颈是你的判断。
▶转型成功的标志

你花在「想清楚要什么、边界在哪、怎么验收」上的时间，开始多于「亲手写」的时间。

3.2 上下文喂饱：把话说清楚

入职第一天，交接开始。行业内再资深的工程师，对你的项目也是一张白纸——项目背景、团队约定、坑和禁区，全在你脑子里。不写下来、不交代清楚，他只能靠猜。Agent 也一样：它的脑子与你的项目无关，上下文全靠你喂（还记得第 1 章吗：记忆 = 上下文）。

交代任务，就是一份好的任务书：目标 + 边界 + 验收。

  • 目标——要达成什么（而不是怎么做）；
  • 边界——不能做什么、哪些不能动；
  • 验收——怎么算完成、怎么验证。

再进一步：把工作方式写进文件。dsh 仓库的 AGENTS.md 就是范例——把规则、约定、边界写成文档，Agent 每次开工自动加载。文档从此不再是给人看的说明书，而是入职手册、人机共享的接口。读到这里的你其实正在实践这件事：这本书的 agents.md，就是这么用的。

图 3-2 一份好的任务书 = 目标 + 边界 + 验收——三样齐了，Agent 才有的放矢。
▶一句话

上下文是新的代码——你交付的不只有实现，还有让实现得以正确发生的全部背景。

3.3 边界管住：护栏与信任

能力越强，越要管住边界。Agent 是概率的（第 1 章讲过），它会犯错——而强者的错，往往更贵。出错时，第一反应不是怪它，而是先查两样东西：边界够不够牢，上下文够不够清。共事哲学的核心张力在于：既放手（否则发挥不出它的价值），又设护栏（否则错误失控）。这两个词放在一起，就是经典原则：信任，但验证。

边界不是固定的，而是随验证逐步放宽——就像试用期：第一天，只让它读代码；第一周，允许它改测试；第一个月，才让它动生产。放权 = 放宽边界，而不是提高能力——它的能力不需要你培养，它的权限需要你验证后再放开。

还记得第 5 章的「可回滚」吗？沙箱、审批、可撤销这些机制（科学篇会讲）都是边界管理的实现——它们都在兑现同一个心法：让错误变得便宜。

图 3-3 边界放宽阶梯：只读 → 改测试 → 动生产，每一步都配护栏。
◆分工

你负责品味，它负责产量。

3.4 放手发挥：便宜是美德

转正之后，就该放手让它干。这样一位资深工程师，请三个也花不了多少——一个试错了，另外两个还在跑。便宜，是 Agent 最被低估的美德：它让你敢试（错了重来），也让你试得起很多次（同时开几个方向）。

传统开发里，「改」很贵，所以人变得保守；Agent 时代里，「试」很便宜，所以心法变成：快速失败、小步迭代、批量实验。

这也正好呼应全书的主线：机制（科学）负责让实验变便宜，品味（艺术）负责在众多结果里挑出好的。

◆心法

把「做快」交给 Agent，把「做对」留给迭代。

3.5 共同进化：自举飞轮

最好的资深工程师，会顺手升级工具链，还会帮团队带新人——这就是自举（bootstrapping）：用 Agent 来构建 Agent 的工具、流程与护栏。

dsh 团队用 AGENTS.md 加 Agent 工作流开发 dsh 本身——Agent 在给自己造更好的工具；而这本书也是自举的产物：人定方向、做判断，Agent 协作产出，再用 agents.md 沉淀共识、指导下一轮。

自举会形成飞轮：Agent 帮你造工具 → 工具让 Agent 更强 → 更强的 Agent 造更好的工具。

图 3-4 自举飞轮：每转一圈，工具与 Agent 都变得更强。
▶最好的例子

你正在读的这本书，就是本章的最佳案例。

一张图总结

图 3-5 第三章的完整脉络：角色之变 → 十六字心法 → 共同进化。

要点回顾

  • 种下一粒种子：你的项目里将出现一位能力比你强的程序员——你的价值变成「喂上下文、管边界、做判断」。
  • 它既不是工具，也不是实习生，而是行业内很资深、只是刚入职的工程师：行业经验足不用教，项目还不熟要喂养。
  • 十六字心法：上下文喂饱、边界管住、放手发挥、共同进化。
  • 边界随验证放宽：只读 → 改测试 → 动生产；护栏让错误变便宜，「可回滚」是护栏的哲学基础。
  • 共同进化：最好的资深工程师会升级工具链——用 Agent 造 Agent 的工具，这本书就是例子。

动手做

这一章的心法，马上就能用：

  1. 写一份任务书：挑一件本周要做的小事，用「目标 + 边界 + 验收」三段式写一份给 Agent 的任务书。
  2. 圈出你的主场：观察自己做一件事时，哪些环节在「动手」、哪些在「判断」？把「判断」圈出来——那才是未来你的主场。
  3. （可选）读一份 AGENTS.md：打开 deepseek-harness 根目录的 AGENTS.md 读一遍，想想哪些约定值得写进你自己的 AGENTS.md。

十六字心法之后，下一章讲怎么让项目活起来——把「上下文喂饱」落成世界观，让项目天生容得下这位新同事。至于 dsh 这具标本的内部构造——到第 8 章，我们再解析它的架构。
