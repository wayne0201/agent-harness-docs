第一篇 · 哲学篇 应用线

第 4 章 · 让项目活起来

会说话，有记性，会成长。

第 2 章说，机器学会了我们的母语；第 3 章说，共事的第一条心法是「上下文喂饱」。这一章把镜头转向你的项目：既然 Agent 只读仓库，项目就得先学会说话；但好项目不止于此——它还要有记性，会吸收反馈。会说话、有记性、会成长——这样的项目，才是活的。

◆本章核心问题

Agent 眼中的好项目长什么样？项目怎么才算「活」起来？

◆全书心法 · 活

会说话，有记性，会成长。

活的项目，才配得上活的 Agent。

▶你将获得

用一个「活」字打量自己的项目：好自述的四个特征、外置记忆的观念、反馈回路的价值——为第 7 章的落地清单打底。

本章导览

  • 4.2 四个特征：会说话

4.1 上下文是 Agent 的原料

第 1 章说过，Agent 的记忆就是上下文。对 Agent 来说，你的项目是它最重要的上下文——它接手任务前，第一件事就是读项目。

但它读项目的方式，和你的同事完全不同：同事带着一脑子记忆来读——需求背景、历史决定、会议结论；Agent 两手空空，只读仓库里写下来的东西。

图 4-1 人带着记忆读项目，Agent 只读仓库——两位读者，看到的是两个项目。

这条鸿沟带来一个残酷的事实：没写下来的，对 Agent 就是不存在的。项目想被读懂，唯一的方式，就是把话说在纸面上——写进仓库。

✦没写下来的 = 不存在

你的记忆、群聊记录、口头约定……对 Agent 都不可见。想让它知道，就写下来。

第 2 章说机器学会了母语——现在轮到你的项目，学会用这门母语介绍自己。这是「活」的第一步：会说话。

4.2 四个特征：会说话

会说话的项目长什么样？像一份好简历：一眼看清你是谁，该写的都写了，规矩提前讲明，关键信息不用追问。四个特征：

图 4-2 会说话的四个特征：文档可读 · 结构清晰 · 约定显式 · 上下文易取。
特征一句话检查问题
文档可读README 说清它是什么、怎么跑新同事 5 分钟能看懂吗？
结构清晰目录一眼看懂，文件各归其位想找的东西 10 秒能找到吗？
约定显式规矩写进文件，不靠默契这条规则写在哪个文件里？
上下文易取关键信息都在仓库里Agent 要的信息，需要问人吗？

别被「做齐」吓住——四个词先记住，第 7 章会给可执行的清单，再配上体检表逐个打勾。

4.3 项目即外置记忆：有记性

「活」的第二步：有记性。把项目当成 Agent 的外置记忆。

模型的知识在参数里：训练时学会的，说不清来源，改不动，也查不到。项目的知识在仓库里：写下来的，可查、可改、可回滚。

图 4-3 参数里的记忆改不动、说不清；仓库里的记忆可查可改——项目是 Agent 的外置记忆。

所以每一次把一句话写进 README、文档或约定文件，都是给 Agent 存了一条长期记忆——这一次你喂给它，下一次它自己会读。这就是第 3 章「上下文喂饱」在项目尺度上的样子。

记忆怎么分层、怎么沉淀——第 10 章展开。

4.4 会吸收反馈，项目才是活的

会说话、有记性，够了吗？还差最后一步——会成长。

静态的项目，README 写完就落灰；活的项目，每一次协作之后都会长大一点：Agent 踩过的坑、你改过的约定、这次学到的结论，顺手写回仓库。下一次，它自己会读。

图 4-4 项目的新陈代谢：用 → 写 → 长，每转一圈，项目长大一点。

这条「用 → 写 → 长」的回路，就是项目的新陈代谢。它转起来，项目越用越顺；它停下来，项目就慢慢变成一具标本。这正是第 3 章十六字的最后一句——「共同进化」——在项目尺度上的样子。

回路怎么转得稳——第 7 章（解析 dsh 的 AI 工程化，看它怎么养自己）、第 10 章（记忆的读取与压缩）、第 12 章（信任与审查）、第 23 章（评估与质量）会逐段展开。而 dsh 自己就是一只活标本——第 7 章先看它怎么说话、怎么长大。

最后留一个问题给下一章：项目要「活」，身体得经得起折腾——今天加一块、明天拆一块，改而不乱。dsh 凭什么做到？答案是构建哲学的第一条：一切皆插件。

一张图总结

图 4-5 第四章的完整脉络：会说话 → 有记性 → 会成长，活的项目配得上活的 Agent。

要点回顾

  • Agent 读项目只读仓库：没写下来的，对它就是不存在的。
  • 会说话：好自述四特征——文档可读 · 结构清晰 · 约定显式 · 上下文易取。
  • 有记性：项目是 Agent 的外置记忆——写进仓库，就是存一条长期记忆。
  • 会成长：每次协作把结论写回仓库，项目就长大一点——「用 → 写 → 长」的新陈代谢。
  • 静态改造的清单在第 7 章；dsh 就是一只活标本（第 8 章）。

动手做

用三件小事，验证你的项目是不是活的：

  1. 假装失忆：忘掉项目的一切背景，只靠仓库里的文件，5 分钟内讲清「这个项目是什么」——卡住的地方，就是它不会说话的地方。
  2. 补一句自述：从四个特征里挑最弱的一个，做一件 10 分钟的小改进：补一句 README、新建一个约定文件、或者把散落的信息挪进文档。
  3. 建一条回路：下一次与 Agent 协作结束后，把一条新结论写回仓库（一句 README、一条约定或一个文档小节）——让「用 → 写 → 长」转起来。
