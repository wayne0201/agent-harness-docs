第 1 章 · 什么是 Agent

从「会计算的程序」到「会行动的智能体」

在学会「构建」之前，我们先回答一个更根本的问题：Agent 究竟是什么？这一章不给你 API，而是给你一个可以随身携带的心智模型。有了它，后面每一章——插件、事件、接缝、循环、日志——都会成为这个模型上自然生长的枝叶。

◆本章核心问题

Agent 到底是什么？它和以前的软件有什么本质不同？

▶你将获得

一个可长期使用的 Agent 心智模型——后续所有章节都在它之上生长；以及一把判断「XX 是不是 Agent」的尺子。

本章导览

  • 1.2 Agent 四要素：感知 · 决策 · 行动 · 记忆

1.1 一个会「行动」的程序

传统程序是一部「输入 → 输出」的确定性机器：你给它确定的输入，它按你写死的规则给出确定的输出。它不会「看情况」，不会「试试看」，更不会「自我修正」。

Agent 不一样。Agent 是一个被赋予了目标、并且能够自主采取行动去达成目标的程序。它在「输入」和「输出」之间，多了一段可以反复运行的循环：观察现状 → 做出决定 → 采取行动 → 记住结果 → 再观察……

举个具体的例子：一个「检查代码并修复失败测试」的 Agent，会运行测试 → 看到失败 → 读报错 → 定位问题 → 修改代码 → 再运行测试 → 直到通过。传统程序做不到这件事，因为它无法在「未知的失败」面前自主决定下一步。

图 1-1 传统程序是一条直线，Agent 是一个循环——这是二者最本质的区别。
▶一个判断口诀

如果程序在「接下来做什么」这件事上需要自己拿主意，它就迈入了 Agent 的领域。

1.2 Agent 四要素：感知 · 决策 · 行动 · 记忆

把 Agent 的循环拆开，它由四个要素驱动：

  • 感知（Perceive）——接收环境信息：用户输入、工具返回、文件内容、错误日志。
  • 决策（Decide）——基于当前信息与目标，选择下一步：调用哪个工具、回复什么。
  • 行动（Act）——执行决策：调用工具、运行命令、产出回复。
  • 记忆（Memory）——保存过程与结果，让「下一步」建立在「上一步」之上。

四个要素不是四个独立的模块，而是一个环。缺了任何一个，循环就会断掉。

图 1-2 四要素构成一个闭环：记忆把上一步的结果送回下一步的感知。
要素一句话例子
感知 Perceive接收环境信息用户输入、工具返回、错误日志
决策 Decide选择下一步做什么调用哪个工具、回复什么
行动 Act执行决策执行命令、写文件、生成回复
记忆 Memory保存过程与结果会话历史、已经做过的事

科普时间：控制论 —— Agent 的前身

1948 年，美国数学家诺伯特·维纳（Norbert Wiener）出版了《控制论》，副标题意味深长：「关于在动物和机器中控制和通信的科学」。他相信动物与机器共享同一套底层规律，那就是反馈（feedback）：系统不断拿「结果」去修正「下一步」。

控制论最经典的例子不是一个程序，而是一台不起眼的家用电器——恒温器：

  1. 你设定目标：26°C；
  2. 传感器读取当前室温，与 26°C 比较，算出偏差；
  3. 太冷 → 加热；刚刚好 → 停止；
  4. 室温变化 → 再读取 → 再比较……
图 1-2a 恒温器：一个最小反馈环——它没有智能，却能在环境忽冷忽热时把室温稳定在目标附近。

类似的循环到处都是：体温调节（冷了发抖产热，热了出汗散热）、骑自行车（每一瞬间微调车把保持平衡）、自动驾驶的车道保持。骑自行车是最好的类比——没有人会在出发前把全程路线规划死，而是在每一刻根据「是不是要倒了」做微调。

控制论留下了两个至今有效的洞见：

  • 反馈让系统不必「预知一切」——它只需要「持续修正」。这正是 Agent 敢于面对未知的底气来源。
  • 「目标—感知—比较—行动」是与载体无关的通用结构——恒温器、自行车手、自动驾驶和 Agent，用的是同一张图纸。
反馈类型作用例子
负反馈 negative feedback缩小偏差，趋向稳定恒温器、骑自行车、Agent 的「试错 + 修正」
正反馈 positive feedback放大偏差，走向极端麦克风啸叫、恐慌抢购、模型幻觉的自我强化

所以，Agent 不是天上掉下来的新物种，而是控制论反馈环的现代版。区别只有一处：恒温器的「比较器」只会算温差，而 Agent 的「决策器」是 LLM——它能把「偏差」理解成「测试报错」「用户不满」「计划受阻」，然后想出一连串行动。环的结构没变，决策器升级了。这也正是下一节要讲的「决策权迁移」。

1.3 LLM 的跃迁：从确定性到概率性

为什么 Agent 在过去几十年没有爆发，而现在爆发了？因为「决策」这一步发生了质变。

  • 自然语言成为通用接口——你不再需要定义精确的输入格式，模型能理解含糊的意图。
  • 泛化能力——同一个模型既能写诗、能写 SQL，还能调用工具，不必为每个任务单独编程。
  • 生成即计划——模型能在行动前「想」出多步计划，而不是死守固定流程。

但这份能力是有代价的：概率性意味着不确定性，意味着「可能出错」。所以 Agent 工程的核心问题之一，就是如何与不确定性共处——这正是第二篇「科学篇」里，接缝、循环、日志这些机制要解决的问题。

图 1-3 LLM 把「决策权」从人写的规则，迁移到了模型的生成。

1.4 与程序 / RPA / Chatbot 的边界

有四样东西很容易被混为一谈。我们用四个维度来区分它们：有没有记忆、能否自主决策、能否调用工具、面对未知怎么办。

图 1-4 四类软件的边界光谱：越往右，自主性越强；跨过「形成闭环」的刻度，才称得上 Agent。
维度普通程序RPA（流程自动化）Chatbot（聊天机器人）Agent
记忆无（除非手写）无长期记忆浅层会话上下文持久记忆
决策固定规则固定流程模型生成回复自主多步决策
工具可调用（路径固定）模拟操作界面通常不主动调用主动调用
面对未知直接报错流程中断可能「编」（幻觉）试错 + 修正
✦边界是渐变的

关键区别不是「有没有用 LLM」，而是是否形成了「感知—决策—行动—记忆」的闭环。一个 Chatbot 加上「能调用工具」，就向 Agent 迈进了一步；一个 RPA 加上「能用 LLM 应对意外」，也向 Agent 迈进了一步。判断标准永远是：它能否在无人逐步指挥的情况下，自己走完一段「想—做—看—再想」的循环。

1.5 心智模型：模型 + 记忆 + 工具 + 循环

把上面的一切收敛成一句话，这就是贯穿全书的那句话：

◆全书心智模型

Agent = 模型（思考）+ 记忆（上下文）+ 工具（行动），由循环（Loop）驱动。

  • 模型（Model）——负责「决策」，对应大语言模型。
  • 记忆（Memory）——负责「感知的累积」，对应会话日志与上下文。
  • 工具（Tools）——负责「行动」，对应文件系统、shell、搜索等能力。
  • 循环（Loop）——负责把它们串起来，反复「想—做—看」。

一个生活化类比：新来的私人助理

如果定义还是抽象，我们把 Agent 想象成一位新来的私人助理：他脑子灵光，但需要你把事情交代清楚，而且时不时要回来问你一句。

比如，你让他订一张下周去上海的机票：他先用脑子想——先查航班（模型）；再用双手打开订票网站（工具）；查完把「没有直飞，只剩中转」写进便签（记忆）；做完这一步，他又回到「想」：中转航班订不订？拿不准，于是回头问你（循环）。你说「可以」——新的一轮循环又开始了。

图 1-5a 助理的工作循环：模型、工具、记忆轮番上阵，循环负责把每一步串起来。
私人助理Agent 心智模型作用
脑子模型 Model理解需求、做决策
便签本记忆 Memory记住任务、偏好、已做过的事
双手 + 电脑 / 电话工具 Tools查资料、打电话、写文件
工作习惯循环 Loop做完一步就检查，再想下一步

把四个零件各拆掉一个，你立刻能感觉到它缺了什么：

  • 拆掉工具 → 只会空谈的顾问：想得头头是道，什么都做不了。
  • 拆掉记忆 → 健忘的助手：每次都要从头讲一遍，还会重复犯同样的错。
  • 拆掉循环 → 只做一步的脚本：查到航班就停下，不会接着订票。
  • 拆掉模型 → 又退回成按固定流程走的自动化脚本（还记得 1.4 的 RPA 吗）。

这套心智模型不是凭空造的词，它精确对应 DeepSeek Harness 的真实结构（第二篇会逐一解剖）：

心智模型职责dsh 对应
模型 Model思考 · 决策llm 包（模型适配器）

◆用这个模型做判断

记住它，你就能回答大多数「XX 是不是 Agent」的问题：它有没有自主决策的模型？有没有持久记忆？能不能调用工具？有没有把它们串起来的循环？缺一个，它就只是 Agent 的某个零件，而不是 Agent。

一张图总结

图 1-6 第一章的完整脉络：四要素 → 心智模型 → 判断标准。

要点回顾

  • Agent 是一个能自主行动、达成目标的程序：在输入与输出之间多了一段「观察—决策—行动—记忆」的循环。
  • 四要素——感知、决策、行动、记忆——缺一不可，它们构成一个环，而非四个孤立的模块。
  • Agent 不是凭空出现的新物种：它是控制论反馈环的现代版——环的结构不变，只是「决策器」从规则升级成了 LLM。
  • LLM 的跃迁在于「决策」这步的质变：从确定规则到概率生成，换来泛化能力，代价是不确定性。
  • Agent 与普通程序 / RPA / Chatbot 的边界在于是否形成闭环，而非是否用了 LLM。
  • 全书心智模型：Agent = 模型 + 记忆 + 工具 + 循环，对应 dsh 的 llm / session / tools / agent-loop。

动手做

这一章不需要写代码，只需要「想」。完成下面三步，你会对 Agent 有手感：

  1. 找一个你常用的软件（订外卖 App、git、搜索引擎……），判断它具备四要素中的哪几项，它是不是 Agent？
  2. 拆一件你最近重复做的事（比如「每天整理下载文件夹」），把它写成四步：感知什么 → 决定什么 → 做什么 → 记住什么。
  3. （可选）体验一次真实的 Agent：运行 npx @deepseek-ai/dsh web，和它对话，观察它什么时候在「想」、什么时候在「调用工具」、什么时候「记住了」你说过的话。

这一章，我们认识了一位新同事——它从控制论里走来，靠一个「观察—决策—行动—记忆」的循环活着。可它为什么恰好在这个时代登场、为什么现在人人都在谈论它？下一章回答：机器学会了我们的母语。
